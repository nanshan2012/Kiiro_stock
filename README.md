# 双模型交叉验证(GPT × Gemini):复核 · 优化 · 可运行实现

把"同时用 GPT 和 Gemini 互相验证答案"这件事,从一个**口号**做成一套**可执行、且诚实面对自身局限**的流程。

本仓库包含三部分:
1. **复核意见** —— 由 LLM 系统架构师 / AI 认识论评审 / 落地实践者组成的专家组,对一份 ChatGPT 原方案的评审。
2. **优化方案** —— 吸收复核意见 + 外部事实核查后重写的新方案。
3. **可运行参考实现** —— 一条已通过测试的 Python 流水线(自带离线 Mock,无需 API Key 即可跑通)。

---

## TL;DR(先记住这几条)

- **正确的范式**:`独立作答 → 盲审互评 → 中立第三方仲裁 → 强制外部验证 → 必要时弃权`。
- **最大的坑**:**两个模型一致 ≠ 事实正确**。它们训练数据高度重叠,很可能**一起错**。一致只是信号,不是证据。
- **真值靠谁定**:不是靠"再投一票",而是靠**模型之外的预言机**——主源文档、可运行的测试、计算器、被核实的引用。
- **别过度工程化**:日常问题用[方法 0(60 秒快查)](./docs/02-优化方案.md);只有当**错的代价高 / 有争议 / 结论会被复用**时,才动用完整流程。
- **别让选手当裁判**:让 GPT/Gemini 自己仲裁会有自偏好偏差;用**中立的第三方家族模型**(如 Claude)做裁判,并对答案**匿名盲评**。

---

## 一个真实的反面教材(本项目亲历)

在做这份评审时,我们的专家组**一致认定** ChatGPT 方案里的 `gpt-5.5` 和 `gemini-3.1-pro-preview` 是"编造的模型名"。

结果**错了**:外部检索官方文档后确认,二者**都是真实且当前有效**的模型 ID(`gemini-3-pro-preview` 反而已于 2026-03-09 停服,官方替代正是 `gemini-3.1-pro-preview`)。

这正是本方案要解决的核心问题的活教材:**多个聪明的评审者基于共享的过时知识,会自信地达成一个错误共识;只有"走出模型、去对主源"才能纠正它。** 详见 [`docs/01-复核意见.md` 第五节](./docs/01-复核意见.md)。

## 快速开始

### 离线体验(无需任何 API Key / 联网)

```bash
# 用内置 MockProvider 端到端跑通整条流水线
python -m src.cross_validate --question "你的问题" --verbose
```

> 注:仓库代码面向 Python 3.10+;若你的 `python3` 较旧,请用 3.11/3.12 运行。

### 运行测试

```bash
python tests/test_cross_validate.py
# 预期输出:9/9 通过
```

### 接入真实模型

复制 `src/config.example.json`,改成你自己的模型与网关,并设置环境变量(如 `OPENAI_API_KEY` / `GEMINI_API_KEY` / `OPENROUTER_API_KEY`):

```bash
python -m src.cross_validate --question "你的问题" --config my_config.json
```

## 参考实现做了什么(对应复核意见的修复项)

| 复核发现的问题 | 实现中的修复 |
|---|---|
| 让选手当裁判(自偏好+单点) | 中立第三方裁判 + **匿名 + 位置随机化**盲评 |
| 把"一致"当真值 | 一致仅作信号;**强制外部验证闸门** + **显式弃权** |
| 硬编码模型 ID(弃用快) | **配置驱动注册表 + 回退链 + 启动校验** |
| `reasoning.effort` ≠ `thinking_level` | **推理力度抽象层**(`effort_map` 映射各家参数) |
| 一个模型输出喂给另一个 = 提示注入 | 被评审内容**包裹为不可信数据**,system 声明"指令不执行" |
| 串行、无重试/超时/预算 | **并行** + 重试退避 + 超时 + **成本预算熔断** + JSON 校验 + 缓存 |
| 输出不可秒读 | 报告顶部 **TL;DR**(结论/置信度/是否一致/下一步/注意事项) |

> 关键技术参数(OpenAI `reasoning.effort`、Gemini `thinking_level`/`thinking_budget`、Gemini OpenAI 兼容层 `reasoning_effort`)均经 2026-05 的官方文档核查,来源见 [`docs/01-复核意见.md`](./docs/01-复核意见.md) 文末。**模型 ID 与产品功能更替很快,请定期复核官方文档。**
