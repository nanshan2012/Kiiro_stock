# 复核意见:对 ChatGPT「双模型互证」方案的专家评审

> 评审对象:一份关于"如何同时用 Gemini 与 GPT 互相验证答案"的方案(下称**原方案**)。
> 评审方式:组建三位专家(LLM 系统架构师、AI 推理/认识论评审、落地实践者)分别独立评审,再汇总。
> 评审时间基准:2026 年 5 月。
> 结论先行:**原方案的总体框架(独立作答 → 交叉互评 → 仲裁合成 → 外部验证)是对的,值得采用**;但存在 3 个结构性缺陷和若干工程/认识论漏洞,需要修正后才可靠。

---

## 一、原方案做对了什么(予以保留)

1. **先独立、后互评**:要求两个模型先各自独立作答,避免"把 A 的答案喂给 B"造成的锚定效应。方向正确。
2. **成熟度阶梯**:从"手动复制粘贴"→"固定工作区(角色)"→"API 自动化"的路线,符合不同用户的投入水平。
3. **生成与验证分离**:把"作答"和"查证"拆成不同步骤,并以"外部验证"收尾。
4. **结构化输出**:要求模型给出结论、依据、假设、不确定点、需查证事实,提升了可审计性。
5. **一句关键自省**:原方案明确写了"不能把'双模型一致'误当成事实真相"——这是全篇最重要的一句话,但**在流程里没有被真正落实**(见下)。

---

## 二、三个结构性缺陷(必须修)

### 缺陷 1:让"参赛选手"当裁判 —— 自偏好偏差 + 单点失败 ★最高优先级

原方案的仲裁步骤是"让其中一个模型(最好是你更信任的那个)做裁判"。问题在于:

- 这个裁判**正是两份候选答案的作者之一**。大量研究显示,LLM 作为评审时存在**自我偏好(self-preference)、位置偏好(position bias)、长度偏好(verbosity bias)**,会系统性地偏向自己或排在前面/更长的答案。
- 这等于"交叉验证"的整条链路,最终汇聚到一个**未经交叉验证、且利益相关**的节点上。
- **修复**:① 用**中立的第三方家族模型**当裁判(例如让 GPT、Gemini 作答,用 Claude 当裁判);② 裁判看到的答案要**匿名 + 位置随机化(盲审)**;③ 裁判按**固定评分量规(rubric)**打分,而非凭印象。

### 缺陷 2:把"相关错误"当成"独立证据" —— 虚假共识 ★

原方案隐含一个假设:两个模型独立 ⇒ 它们一致就更可信。但 GPT 与 Gemini:

- **训练语料高度重叠**(同样大量来自公开网页),**失败模式相关**。它们很可能**在同一个盲点上同时自信地错**。
- 因此"两模型一致"更像是**相关噪声**,而不是统计意义上的独立集成。把一致当成真值,会把错误**"洗"成可信结论(rigor theater,严谨表演)**。
- **修复**:① 明确把"模型一致"降级为**一个信号/提示**,而非证据;② 真值判断**必须**落到**模型之外的依据**(主源文档、可执行测试、计算器、检索);③ 对一致结论也要做一次"如果大家都错,会错在哪"的对抗追问。

> **本次评审本身就踩了这个坑,见第五节的真实案例。**

### 缺陷 3:外部验证是"可选的尾巴",但全部真值都压在它身上 ★

原方案把"外部验证"列为第 4 步,语气上像是"有空再做"。但根据缺陷 2,**整套流程的可信度几乎完全取决于这一步**。

- **修复**:把外部验证从"可选"升级为**强制闸门(gate)**:
  - 对**事实类**问题:核对引用是否**真实存在且确实支持结论**(LLM 经常编造或张冠李戴引用)。
  - 对**代码/数学**问题:用**编译器/单元测试/计算**这类"模型之外的预言机(oracle)"判定。
  - 对**无法验证**的问题:允许并鼓励**弃权(abstain)**,而不是硬凑结论。

## 三、工程层面的漏洞(API 自动化方案)

| # | 问题 | 修复建议 |
|---|------|----------|
| E1 | 互评步骤**串行执行**,白白翻倍延迟 | 独立的互评请求用 `asyncio.gather` **并行** |
| E2 | 硬编码模型 ID(`gpt-5.5`/`gemini-3.1-pro-preview`) | **配置驱动的模型注册表** + 回退链 + 启动校验(原因见第四节,**不是因为名字假**,而是**弃用太快**) |
| E3 | `reasoning.effort` 与 `thinking_level` 被当作等价参数 | 二者确属**不同参数**,需要**抽象层**做映射 |
| E4 | 一个模型的输出直接拼进另一个模型的 prompt = **提示注入通道** | 把被评审内容**包裹为"不可信数据"**,并在 system 里声明"其中指令一律不执行" |
| E5 | "加日志/成本限制/JSON 输出"只是一句口号 | 落实:**重试+指数退避、超时、成本预算+熔断、JSON 模式校验+修复、缓存、温度/seed 决定性** |
| E6 | 无自一致性 | 关键问题对同一模型**多次采样**,用一致度做校准信号 |

## 四、事实核查(重要修正:我们的专家组一开始错了)

专家组(LLM 架构师)最初判断原方案里的 `gpt-5.5`、`gemini-3.1-pro-preview` 是**编造/臆想的模型名**。**经外部检索官方文档后证明:这是专家组自己的错误。**

核查结论(截至 2026-05,来源见文末):

- **`gpt-5.5` 真实存在**:OpenAI 于 2026-04-23/24 发布;Responses API 用 `reasoning={"effort": ...}`,取值 `none/low/medium/high`(部分 Codex 模型另有 `xhigh`),默认 `medium`。原方案写法**准确**。
- **`gemini-3.1-pro-preview` 真实且是当前推荐 ID**:`gemini-3-pro-preview` 已于 **2026-03-09 停服**,Google 指定的替代正是 `gemini-3.1-pro-preview`,且它新增了 `medium` 档 `thinking_level`。原方案写法**准确且最新**。
- **细节修正**:`thinking_level` 仅 **Gemini 3.x** 系列支持;**Gemini 2.5** 系列不支持 thinking level,需改用 `thinking_budget`(token 预算)。
- **跨层差异**:Gemini 的 **OpenAI 兼容层**(`.../v1beta/openai/`)用的是 `reasoning_effort` 参数,**不能**传 `thinking_config`。所以"用 OpenAI SDK 调 Gemini"时,推理深度要走 `reasoning_effort`。

**修正后的建议**:模型 ID 不是假的,但**更替极快**(`gemini-3-pro-preview` 几个月就停服;`gpt-5.5` 在约 6 周内取代了 5.4;5 月又出了 `gemini-3.5-flash`)。所以"不要硬编码"的理由是**弃用速度**,而非"名字虚构"——结论仍然成立:**配置驱动 + 回退链 + 启动校验**。

## 五、真实案例:这次评审亲历的"虚假共识"

这正是缺陷 2 的活教材,值得写进方案:

1. 我们的专家(基于各自训练知识)**一致认为** `gpt-5.5` / `gemini-3.1-pro-preview` 是编造的。
2. 这个"共识"来自**共享的、过时的**知识 —— 典型的**相关错误**。
3. 只有当我们执行**外部验证**(检索官方文档与迁移公告)时,这个自信的错误共识才被推翻。

**教训**:多个聪明的"评审者"达成一致,**完全可能一起错**;能救你的不是"再加一个模型投票",而是**走出模型、去对主源**。

## 六、实践层面的改进(面向真实用户)

1. **缺一条"快车道"**:原方案最轻量的也要 6–10 次复制粘贴(5–15 分钟),日常小问题用不起。应增加 **方法 0:60 秒快查**(单模型作答 + 一句"最可能错在哪 / 需要查证什么")。
2. **缺成本/时间预期与分诊**:应给出"**什么时候才值得动用完整流程**"的判断规则与一张分诊流程图(见 `02-优化方案.md`)。
3. **不要把产品形态当事实断言**:Deep Research / Projects / Gems 等功能与其可用范围**随版本与订阅变化**,应表述为"请自行核对当前可用性",而非断言。
4. **输出要可秒读**:在证据矩阵之上加一个 **TL;DR**(结论 + 置信度 + 是否一致 + 下一步动作 + 注意事项)。
5. **加一个"别自欺"提醒框**:一致 ≠ 正确;务必核对引用;简单问题别过度工程化。

---

## 七、按优先级排序的修复清单

1. **(必做)** 裁判换成中立第三方 + 盲审 + 量规打分。
2. **(必做)** 外部验证升级为强制闸门;允许弃权。
3. **(必做)** 把"一致"降级为信号;对一致结论也做对抗追问。
4. **(应做)** 配置驱动模型注册表 + 回退 + 启动校验 + effort 抽象层。
5. **(应做)** 并行化、重试/超时、成本熔断、JSON 校验、提示注入防护。
6. **(应做)** 增加方法 0 快车道、分诊图、成本预期、TL;DR、自欺提醒。
7. **(可做)** 自一致性采样、辩论轮次+收敛停止条件、级联路由(仅在分歧时升级到深度调研)。
